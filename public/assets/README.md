# GLB models

Drop `.glb` files here (served at `/assets/...`) and list them in `packages/domain/src/world-data/assets.json`:

```json
{ "id": "palm", "url": "/assets/props/palm.glb", "slot": "prop:tree", "zones": ["library", "student_commons"],
  "maxBytes": 120000, "maxTriangles": 2500, "size": { "w": 2.4, "h": 4, "d": 2.4 } }
```

- `slot: "prop:<kind>"` replaces every prop of that kind (tree, bench, shelf, counter, pillar, fountain, stage, block). `building:<id>` (per-building facade trim) and `decor:<name>` (zone `decor` placements) are wired too; NPC/avatar slots are reserved.
- Models are streamed when the player enters a listed zone; the previous zone stays resident, older ones are evicted. `"zones": "all"` keeps it resident.
- Budgets: per-asset `maxBytes`/`maxTriangles` (defaults in the manifest) and a total `residentBudget`. Over budget, 404 or a bad file = that slot silently keeps the built-in shape and a `[assets]` warning is logged.
- Supported: glTF 2.0 binary, triangles, node transforms, material baseColorFactor / COLOR_0 (baked to vertex colour). Not supported yet: textures, Draco/meshopt, sparse accessors, skinning/animation. Compress meshes (quantised, <2.5k tris per prop) and keep each file well under the byte budget.
- Models are auto-normalised to a unit box with the base at ground level, then scaled to `size` (or the prop footprint).

## Shipped models
`props/*.glb` are generated by `node scripts/models/generate-props.mjs` (re-running it rewrites the GLBs, `assets.json` and the `decor`
lists in the zone files, so hand-edit zone `decor` only after you stop using the generator, or move your edits into the script).
Decor slots use `"slot": "decor:<name>"` and are placed per zone via `decor: [{ "model": "lamp_post", "x": 56.3, "y": 8, "rot": 0 }]`.
